02 Semantic Tokens

Theme-aware aliases built from the primitives above. Light is always the default — dark only applies once toggled via the navbar, never from prefers-color-scheme. Toggle the button top-right to preview both. Lesson learned this pass: the Work-card hover state originally darkened text toward a fixed grey for "more contrast" — correct in light mode, backwards in dark mode, where darkening a light-on-dark color loses contrast. Fixed by using --text-color for hover instead of a fixed grey — it flips with the theme, so hover gains contrast in both directions. Prefer a semantic token over a fixed primitive whenever a state needs to read correctly in both themes.

06 Motion

New this pass — an overshoot/bounce easing for interactions with a physical, "pulled and it springs" feel, first built for the Work-card folder reveal.

--ease-bounce: cubic-bezier(0.34, 1.56, 0.64, 1); — hover the track. Used one-directionally in practice: it overshoots past its target before settling, which reads fine when something is arriving (the folder card's hover-in), but the same overshoot on the way back out can flash a visible glitch — e.g. briefly exposing a gap past an edge that's supposed to stay covered. The fix used on the folder card: bounce only on the transition into the new state; fall back to plain ease-out for the return, since CSS transitions pick up whichever rule's transition property belongs to the state being entered.
